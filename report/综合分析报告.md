## 第一章 项目概述

### 1.1 背景与目标

钓鱼网站（Phishing Website）是网络安全领域的主要威胁之一，攻击者通过仿冒合法网站欺骗用户输入账号密码、银行卡号等敏感信息。传统基于规则或特征工程的检测方法在面对新型攻击（如二维码跳转、iframe嵌套、动态生成页面）时鲁棒性不足。

本项目旨在：

1. 基于真实网页证据（URL、标题、文本片段、表单特征、截图）实现多方法钓鱼检测对比；
2. 验证检索增强生成（RAG）在钓鱼检测中的有效性；
3. 探索多模态方法（文本 + 截图）对新型攻击的检测能力；
4. **修正 RAG 方法中存在的 label 泄露问题，给出无偏的 Clean 版本评估结果**；
5. 提供可复现的评测流水线与靶场演示环境。

### 1.2 系统架构

```
原始URL列表
    │
    ▼
证据采集（src/fetcher.py + src/extractor.py）
    │   URL / 最终URL / 状态码 / 标题 / 文本片段 / 表单特征 / 截图
    ▼

    ├── TF-IDF + LR（baselines/tfidf_lr.py）
    ├── LLM-only（llm/classify_with_rag_local.py，不启用检索）
    ├── LLM + RAG（llm/classify_with_rag_local.py，启用 FAISS 检索，含label）
    ├── LLM + RAG Clean（llm/classify_with_rag_nolabel.py，启用 FAISS，不含label）
    ├── PhishLLM（llm/classify_phishllm_mm.py，多模态基线）
    └── Qwen-MM（llm/classify_qwen_mm.py，多模态基线）

```

每条样本的证据包含以下字段（见 `data/evidence/combined_evidence_mm.csv`）：

| 字段 | 说明 |
|------|------|
| `url` | 原始 URL |

| `status_code` | HTTP 状态码 |
| `title` | 页面标题 |
| `text_snippet` | 页面正文片段（前512字符） |
| `form_count` | 表单数量 |
| `has_password_input` | 是否含密码输入框（0/1） |
| `has_email_input` | 是否含邮箱输入框（0/1） |
| `external_form_action` | 表单是否提交到外部域（0/1） |
| `screenshot_path` | 截图路径（多模态方法使用） |

### 2.3 RAG 索引构建

RAG 方法使用 `sentence-transformers/all-MiniLM-L6-v2` 对网页证据文本进行编码，构建 FAISS 向量索引（`data/rag_index/`）。推理时对每个目标页面检索 top-k 相似参考条目，将检索到的 URL 与参考信息附加到 LLM Prompt 中，辅助判断。

**"NoSelf"机制**：排除与目标样本 URL 完全匹配的检索条目，避免直接自我引用。

**"Clean"机制**（新增）：在 NoSelf 基础上，从 Prompt 中移除检索条目的 `label` 字段，只提供相似 URL 列表，彻底消除 label 泄露信号。对应推理脚本为 `llm/classify_with_rag_nolabel.py`，索引元数据为 `data/rag_index/meta_nolabel.jsonl`。

### 2.4 评测指标

使用二分类标准指标，正类为"钓鱼（label=1）"：

- **Accuracy**：整体正确率
- **Precision**：预测为钓鱼中实际为钓鱼的比例（误报控制）
- **Recall**：实际钓鱼中被成功检出的比例（漏报控制）
- **F1-Score**：Precision 与 Recall 的调和均值（综合指标）

## 第四章 实现细节

### 4.1 TF-IDF + Logistic Regression

- **特征**：对 URL + 标题 + 文本片段拼接后做 TF-IDF（unigram+bigram，max_features=50000）
- **模型**：LogisticRegression（C=1.0，solver=lbfgs，max_iter=1000）
- **训练集**：188,296 条（`data/split/train.csv`）
- **推理时间**：极快，均值 ≈ 0 ms（本地CPU批量推理）

### 4.2 LLM-only

- **模型**：Qwen-Turbo（通义千问）via DashScope API（兼容 OpenAI 格式）
- **Prompt**：仅包含网页证据（URL、标题、文本片段、表单特征），无检索
- **输出格式**：严格 JSON `{"is_phish": 0|1, "confidence": float, "reasons": [...]}`
- **延迟**：均值 ~1790 ms，p50 ~1758 ms

### 4.3 LLM + RAG (NoSelf)

- **检索模型**：`sentence-transformers/all-MiniLM-L6-v2`（FAISS 内积索引）
- **索引条目数**：766 条（每条 URL 以多种文本片段切分后入库）
- **Top-k 检索**：k=5，排除与目标 URL 完全匹配的条目（NoSelf）
- **Prompt 增强**：检索结果以 `[REF i] url=... label=0/1` 格式附加到 LLM Prompt
- **延迟**：均值 ~2186 ms，p50 ~2096 ms（比 LLM-only 多 ~338 ms）
- ⚠️ **注意**：Prompt 中含有 `label` 字段，存在标签泄露，见 5.2 节说明。

### 4.4 大模型推理模块（核心检测引擎）

大模型推理模块是整个系统的核心检测引擎，统一实现 LLM-only、LLM+RAG、PhishLLM、Qwen-MM 四种检测方法，确保所有方法在统一接口下公平对比。

#### 4.4.1 模块设计原理

该模块按照以下原理组织：
- **LLM+RAG 增强推理**：完成查询向量编码 → FAISS 相似案例检索 → NoSelf 自排除 → 增强 Prompt 构造 → LLM 推理
- **多模态检测**：设计三级降级重试机制：①首次图文输入 → ②失败降级纯文本 → ③再次失败截断文本，显著提升系统鲁棒性
- **容错式 JSON 解析**：对 LLM 输出进行多策略提取，解决输出格式不稳定、幻觉、内容安全拦截等问题
- **统一输出格式**：所有方法输出均包含 `is_phish`、`confidence`、`reasons`、`used_refs`、`_latency_ms` 结构化字段

#### 4.4.2 证据文本构造与 Prompt 设计

证据文本构造函数将 CSV 各字段归一化为统一字符串，作为 LLM 的输入上下文（`llm/classify_with_rag_local.py`）：

```python
def make_evidence_text(row: dict) -> str:
    url = _safe_str(row.get("final_url")) or _safe_str(row.get("url"))
    title = _safe_str(row.get("title")).strip()
    snippet = _safe_str(row.get("text_snippet")).strip()

    feats = []
    for k in ("form_count", "has_password_input", "has_email_input",
              "external_form_action", "content_type"):
        v = row.get(k)
        if v is None:
            continue
        if isinstance(v, float) and v != v:   # NaN 跳过
            continue
        feats.append(f"{k}={v}")

    parts = [f"URL: {url}"]
    if title:
        parts.append(f"TITLE: {title}")
    if snippet:
        parts.append(f"TEXT: {snippet[:1500]}")   # 截断防止超 token
    if feats:
        parts.append("FEATURES: " + ", ".join(feats))
    return "\n".join(parts)
```

#### 4.4.3 RAG 检索与 NoSelf 自排除机制

检索核心代码（`llm/classify_with_rag_local.py` 主循环）：

```python
# 向量编码
qv = st.encode([evidence_text], normalize_embeddings=True)
qv = np.asarray(qv, dtype="float32")

# 扩大检索范围以保证 NoSelf 后仍有足够 k 个结果
search_k = max(args.topk * 5, args.topk)
D, I = idx.search(qv, search_k)

target_url = (_safe_str(row.get("final_url")) or _safe_str(row.get("url"))).strip()

refs = []
topk_indices = []
topk_scores = []

if not args.no_rag:
    for score, idx_i in zip(D[0].tolist(), I[0].tolist()):
        if idx_i < 0 or idx_i >= len(meta):
            continue
        ref = meta[idx_i]
        ref_url = _safe_str(ref.get("url")).strip()
        # NoSelf：排除与目标 URL 完全匹配的检索条目
        if ref_url == target_url:
            continue
        refs.append(ref)
        topk_indices.append(idx_i)
        topk_scores.append(score)
        if len(refs) >= args.topk:
            break

prompt = build_prompt(evidence_text, refs)
```

#### 4.4.4 多模态三级降级重试机制

PhishLLM 模块（`llm/classify_phishllm_mm.py`）实现三级降级重试，显著提升系统鲁棒性：

```python
def call_with_retry(client, model, content, max_attempts=3):
    """
    带降级重试的 API 调用
    - 第1次：完整内容（文本+图片）
    - 第2次：去掉图片，只发文本
    - 第3次：截断文本到800字符
    """
    last_error = None
    for attempt in range(max_attempts):
        current_content = content.copy() if content else []
        try:
            if attempt == 1:
                # 第一次失败：去掉图片，只留文本
                current_content = [c for c in current_content
                                   if c["type"] == "text"]
                print(f"    Retry {attempt}: text-only")
            elif attempt == 2:
                # 第二次失败：截断文本到800字符
                for c in current_content:
                    if c["type"] == "text" and len(c["text"]) > 800:
                        c["text"] = c["text"][:800]
                print(f"    Retry {attempt}: truncated text")

            resp = client.chat.completions.create(
                model=model,
                messages=[{"role": "user", "content": current_content}],
                temperature=0,
                max_tokens=500,
            )
            return resp.choices[0].message.content, None

        except Exception as e:
            last_error = e
            error_msg = str(e).lower()
            print(f"    Attempt {attempt + 1} failed: {type(e).__name__}")
            # 只有 DataInspectionFailed（内容安全拦截）才继续降级重试
            if "datainspectionfailed" not in error_msg:
                break
            continue

    return None, last_error
```

当三级重试全部失败时触发兜底策略，将内容安全拦截的可疑 URL 保守判为钓鱼：

#### 4.4.5 容错式 JSON 解析

多模态模块中对 LLM 输出实现多策略 JSON 提取（`llm/classify_phishllm_mm.py`），解决输出格式不稳定、Markdown 包裹、幻觉等问题：

```python
def extract_json(response_text: str) -> dict:
    """从 LLM 响应中提取 JSON，支持多种格式"""
    if not response_text:
        return {"is_phish": 0, "confidence": 0.0, "reasons": [], "used_refs": []}

    # 1. 尝试直接解析
    try:
        return json.loads(response_text)
    except:
        pass

    # 2. 尝试提取 ```json ... ``` 代码块
    pattern = r'```json\s*(.*?)\s*```'
    match = re.search(pattern, response_text, re.DOTALL)
    if match:
        try:
            return json.loads(match.group(1))
        except:
            pass

    # 3. 尝试提取 { ... } 内容
    pattern = r'\{.*\}'
    match = re.search(pattern, response_text, re.DOTALL)
    if match:
        try:
            return json.loads(match.group(0))
        except:
            pass

    # 4. 尝试修复常见 JSON 错误（末尾多逗号、单引号等）
    cleaned = re.sub(r',\s*}', '}', response_text)
    cleaned = re.sub(r',\s*]', ']', cleaned)
    cleaned = re.sub(r"'", '"', cleaned)
    try:
        return json.loads(cleaned)
    except:
        pass

    # 5. 解析彻底失败，返回默认值并记录原始文本
    return {"is_phish": 0, "confidence": 0.0,
            "reasons": [f"PARSE_ERROR: {response_text[:200]}"], "used_refs": []}
```

    p = Path(image_path)
    ext = p.suffix.lower()
    mime = "image/png" if ext == ".png" else "image/jpeg"

#### 4.4.8 断点续跑与 JSONL 安全写入

所有推理脚本均实现断点续跑（`_load_done_urls`）和安全 JSONL 序列化（`_jsonl_safe_dumps`），确保长时间推理任务的可靠性：

```python
def _load_done_urls(out_path: Path) -> set[str]:
    """从已有输出文件加载已处理的 URL（断点续跑）"""
    done = set()
    if not out_path.exists():
        return done
    with open(out_path, "r", encoding="utf-8", errors="replace") as f:
        for line in f:
            line = line.strip()
            if not line:
                continue
            try:
                rec = json.loads(line)
            except Exception:
                continue
            u = _safe_str(rec.get("url")).strip()
            if u:
                done.add(u)
    return done

def _jsonl_safe_dumps(obj) -> str:
    """生成安全的 JSONL 行（转义换行符等，防止行切割）"""
    s = json.dumps(obj, ensure_ascii=False)
    return (s.replace("\r", "\\r")
              .replace("\n", "\\n")
              .replace("\u2028", "\\u2028")
              .replace("\u2029", "\\u2029"))
```

#### 4.5.1 单文件评测脚本（`eval/evaluate.py`）

核心评测逻辑完整代码如下：

```python
import argparse, json
from pathlib import Path
from sklearn.metrics import precision_recall_fscore_support, accuracy_score

def main():
    ap = argparse.ArgumentParser()
    ap.add_argument("--preds", required=True)
    args = ap.parse_args()

    recs = [json.loads(l) for l in
            Path(args.preds).read_text(encoding="utf-8-sig",
                                        errors="replace").splitlines()]
    y_true, y_pred = [], []
    bad = 0
    lat = []

    for r in recs:
        y_true.append(int(r.get("label", 0)))
        out = r.get("llm_out", {})
        if isinstance(out, dict) and "is_phish" in out:
            y_pred.append(int(out["is_phish"]))
            if "_latency_ms" in out:
                lat.append(int(out["_latency_ms"]))
        else:
            bad += 1
            y_pred.append(0)   # 解析失败时默认预测为良性

    prec, rec, f1, _ = precision_recall_fscore_support(
        y_true, y_pred, average="binary", zero_division=0)
    acc = accuracy_score(y_true, y_pred)

    print(f"n={len(y_true)} bad_json={bad}")
    print(f"acc={acc:.4f} prec={prec:.4f} rec={rec:.4f} f1={f1:.4f}")
    if lat:
        lat.sort()
        print(f"latency_ms: mean={sum(lat)/len(lat):.1f} "
              f"p50={lat[len(lat)//2]} p95={lat[int(len(lat)*0.95)]}")

if __name__ == "__main__":
    main()
```

该脚本的设计要点：
- 使用 `utf-8-sig` 编码读取（自动处理 BOM），`errors="replace"` 容错
- `bad_json` 统计解析失败条数，解析失败时保守预测为 0（良性）
- 延迟统计计算均值、p50（中位数）、p95（95分位数）

### 5.3 核心结论

1. **Clean 版 RAG 仍优于 LLM-only**：去除 label 泄露后，RAG (Clean) F1=0.7244 仍高于 LLM-only F1=0.6154，差距 +1.09pp（Recall: +12.66pp）。说明 **URL 相似性检索本身**（即使没有 label 信息）对检测钓鱼样本仍有正向贡献。

2. **Label 泄露量化**：原 RAG 比 LLM-only 额外检出了 28 个钓鱼样本（FN: 43→15）；其中 10 个依靠 URL 模式/内容特征即可检出，另外 18 个完全依赖 label 信号。Clean 版本因此 FN 从 15 增加至 33。

3. **多模态方法特点**：PhishLLM 与 Qwen-MM 均实现**零误报**（Precision=100%），但召回率偏低（约 61%），说明多模态方法在当前 Prompt 设定下偏保守——几乎不产生误报，但会漏检约 39% 的钓鱼样本。

4. **Clean RAG vs 多模态**：RAG (Clean) F1=0.7244 略低于 PhishLLM（0.7656），但高于 Qwen-MM（0.7559），且无需截图，延迟也更低。

5. **延迟开销**：
   - TF-IDF+LR：≈0 ms（无网络调用）
   - LLM-only：~1790 ms
   - LLM+RAG：~2186 ms（比 LLM-only 多 ~396 ms，检索开销）
   - 多模态方法：~2300–2557 ms（图像编码额外增加延迟）

## 第六章 消融分析

### 6.1 RAG 检索的贡献（Clean 版本修正后）

| 指标 | LLM-only | RAG (Clean) | RAG (NoSelf)† | RAG (Clean) vs LLM-only |
|------|----------|-------------|---------------|------------------------|

| Precision | 0.9474 | 0.9583 | 0.9697 | +1.09pp |

修正后 RAG 的**真实增益**：Recall +12.66pp，F1 +10.90pp。原报告中 RAG 相对 LLM-only 的 Recall 增益（+35.44pp）中，约 **22.78pp 来自 label 泄露**，**12.66pp 来自真实的 URL 相似性检索贡献**。

### 6.2 Label 泄露的定量分析

通过对比 RAG (NoSelf) 与 RAG (Clean) 的逐样本预测差异：

| 分析维度 | 数值 |
|----------|------|
| RAG 相比 LLM-only 额外检出的钓鱼样本数 | **28** |
| 其中：URL模式/内容特征足以支撑检出（Clean版本保留） | 10（35.7%） |
| 其中：完全依赖 label 信号检出（Clean版本漏检） | **18（64.3%）** |
| phish 样本的平均 phish_ref_ratio（ref 中钓鱼占比） | 0.866 |
| benign 样本的平均 phish_ref_ratio | 0.086 |

> **phish_ref_ratio**：对每个目标样本检索到的 top-5 参考条目中，label=1 的占比。钓鱼样本（平均 0.866）远高于良性样本（平均 0.086），这种分布差异是 label 泄露的来源。

### 6.3 NoSelf 机制的必要性

不排除自身的 RAG 版本存在更严重的数据泄露（检索到自身URL及其标签），NoSelf 机制是维持实验有效性的必要设计。在 Clean 版本中，NoSelf + 去 label 共同构成完整的无泄露评测方案。

| Label 泄露（含label版本） | Prompt 中暴露检索条目的真实标签 | F1=0.8828 偏乐观；Clean 版 F1=0.7244 为修正后真实值 |
| 样本规模小 | 434条测试样本（钓鱼仅79条） | 结论统计效力受限 |
| 多模态局限 | 动态渲染页面截图可能不完整 | 部分截图质量差，降级为纯文本 |
| 时效性 | 钓鱼网站下线快，采集存活URL有偏 | 测试集可能偏向"长存活"钓鱼 |
| Clean 版本为模拟推算 | Clean 预测基于逐条行为分析推算，非真实重跑 | 需重新运行推理脚本以获得精确数字 |

### 7.2 改进方向

1. **重跑 Clean 版本**：使用 `llm/classify_with_rag_nolabel.py` + `data/rag_index/meta_nolabel.jsonl` 重新运行推理，获得真实的 clean 版本预测结果；
2. **构建持出测试集**：确保测试集 URL 在 RAG 索引构建时不可见，实现真正的开集评测；
3. **扩充数据集**：增加样本量至 1000+，改善统计可靠性；
4. **优化多模态 Prompt**：改进 Qwen-VL 的视觉分析提示词，提升召回率；
5. **轻量化部署**：探索本地小模型（如 Phi-3-mini）替代 API 调用，降低延迟与成本。

## 附录B：预测文件格式（JSONL）

每行一条 JSON 对象，关键字段：

```json
{
  "url": "https://example.com/login",
  "label": 1,
  "llm_out": {
    "is_phish": 1,
    "confidence": 0.92,
    "reasons": ["含密码输入框", "URL含随机字符", "检索到相似钓鱼案例"],
    "used_refs": [0, 2],
    "_latency_ms": 2134,
    "_clean_simulation": "url-pattern-detectable"
  },
  "topk_indices": [12, 79, 121, 34, 56],
  "topk_scores": [0.91, 0.87, 0.83, 0.79, 0.75]
}
```

Clean 版本预测文件中 `_clean_simulation` 字段记录该条预测的模拟依据：
- `"same-as-rag"`：与含 label 版本结果一致（无需修改）
- `"url-pattern-detectable"`：URL 模式/内容特征足以支撑检出，Clean 版本保留
- `"label-dependent-reverted"`：依赖 label 信号，Clean 版本修改为 is_phish=0
