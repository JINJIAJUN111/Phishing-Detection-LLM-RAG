## 第一章 项目概述

### 1.1 背景与目标

钓鱼网站（Phishing Website）是网络安全领域的主要威胁之一，攻击者通过仿冒合法网站欺骗用户输入账号密码、银行卡号等敏感信息。传统基于规则或特征工程的检测方法在面对新型攻击（如二维码跳转、iframe嵌套、动态生成页面）时鲁棒性不足。

本项目旨在：

1. 基于真实网页证据（URL、标题、文本片段、表单特征、截图）实现多方法钓鱼检测对比；
2. 验证检索增强生成（RAG）在钓鱼检测中的有效性；
3. 探索多模态方法（文本 + 截图）对新型攻击的检测能力；
4. 提供可复现的评测流水线与靶场演示环境。

### 1.2 系统架构

```
原始URL列表
    │
    ▼
证据采集（src/fetcher.py + src/extractor.py）
    │   URL / 最终URL / 状态码 / 标题 / 文本片段 / 表单特征 / 截图
    ▼
多方法推理层
    ├── TF-IDF + LR（baselines/tfidf_lr.py）
    ├── LLM-only（llm/classify_with_rag_local.py，不启用检索）
    ├── LLM + RAG（llm/classify_with_rag_local.py，启用 FAISS 检索）
    ├── PhishLLM（llm/classify_phishllm_mm.py，多模态基线）
    └── Qwen-MM（llm/classify_qwen_mm.py，多模态基线）
    │
    ▼
预测结果（data/predictions/*.jsonl）
    │
    ▼
统一评测（eval/evaluate.py / eval/summary_table.py）
    │
    ▼
图表生成（tools/make_plots_final.py）
```

### 1.3 方法列表（5种）

| 编号 | 方法 | 模态 | 说明 |
|------|------|------|------|
| M1 | TF-IDF + Logistic Regression | 纯文本 | 传统机器学习基线 |
| M2 | LLM-only | 纯文本 | 不使用检索，直接提示 LLM |
| M3 | LLM + RAG (NoSelf) | 纯文本 | 本文核心方案，FAISS 检索增强，排除自身 |
| M4 | PhishLLM (MM baseline) | 文本+截图 | 参考 USENIX Security 2024 |
| M5 | Qwen-MM (img+text) | 文本+截图 | 基于 Qwen-VL 的多模态推理 |

## 第二章 数据集与实验设置

### 2.1 数据集概述

| 字段 | 数值 |
|------|------|
| 测试集总样本数 | 434 |
| 钓鱼样本（phish, label=1） | 79（18.2%） |
| 良性样本（benign, label=0） | 355（81.8%） |
| 截图覆盖率 | 424/434 = **97.7%** |
| 无截图样本处理 | 自动退化为纯文本推理 |

> **截图覆盖率说明**：基于 `data/evidence/combined_evidence_mm.csv` 直接统计，`screenshot_path` 字段非空行数为 424，共 434 行，覆盖率 97.7%。无截图样本在多模态推理中自动降级为文本模式。

数据来源：
- 钓鱼样本：OpenPhish 公开 Feed 经过滤后的可访问 URL
- 良性样本：Tranco Top List 低风险域名经过滤后的可访问 URL

训练集（供 TF-IDF + LR 使用）：188,296 条；验证集 / 测试集各 23,537 条（大型数据集），此外构建了本地 434 条精细证据集用于 LLM / RAG 评测。

### 2.2 证据特征字段

每条样本的证据包含以下字段（见 `data/evidence/combined_evidence_mm.csv`）：

| 字段 | 说明 |
|------|------|
| `url` | 原始 URL |
| `final_url` | 跟随重定向后的最终 URL |
| `status_code` | HTTP 状态码 |
| `title` | 页面标题 |
| `text_snippet` | 页面正文片段（前512字符） |
| `form_count` | 表单数量 |
| `has_password_input` | 是否含密码输入框（0/1） |
| `has_email_input` | 是否含邮箱输入框（0/1） |
| `external_form_action` | 表单是否提交到外部域（0/1） |
| `screenshot_path` | 截图路径（多模态方法使用） |

### 2.3 RAG 索引构建

RAG 方法使用 `sentence-transformers/all-MiniLM-L6-v2` 对网页证据文本进行编码，构建 FAISS 向量索引（`data/rag_index/`）。推理时对每个目标页面检索 top-k 相似参考条目，将检索到的 URL 与参考信息附加到 LLM Prompt 中，辅助判断。

**"NoSelf"机制**：排除与目标样本 URL 完全匹配的检索条目，避免直接自我引用。

### 2.4 评测指标

使用二分类标准指标，正类为"钓鱼（label=1）"：

- **Accuracy**：整体正确率
- **Precision**：预测为钓鱼中实际为钓鱼的比例（误报控制）
- **Recall**：实际钓鱼中被成功检出的比例（漏报控制）
- **F1-Score**：Precision 与 Recall 的调和均值（综合指标）

## 第四章 实现细节

### 4.1 TF-IDF + Logistic Regression

- **特征**：对 URL + 标题 + 文本片段拼接后做 TF-IDF（unigram+bigram，max_features=50000）
- **模型**：LogisticRegression（C=1.0，solver=lbfgs，max_iter=1000）
- **训练集**：188,296 条（`data/split/train.csv`）
- **推理时间**：极快，均值 ≈ 0 ms（本地CPU批量推理）

### 4.2 LLM-only

- **模型**：Qwen-Turbo（通义千问）via DashScope API（兼容 OpenAI 格式）
- **Prompt**：仅包含网页证据（URL、标题、文本片段、表单特征），无检索
- **输出格式**：严格 JSON `{"is_phish": 0|1, "confidence": float, "reasons": [...]}`
- **延迟**：均值 ~1790 ms，p50 ~1758 ms

### 4.3 LLM + RAG (NoSelf)

- **检索模型**：`sentence-transformers/all-MiniLM-L6-v2`（FAISS 内积索引）
- **索引条目数**：766 条（每条 URL 以多种文本片段切分后入库）
- **Top-k 检索**：k=5，排除与目标 URL 完全匹配的条目（NoSelf）
- **Prompt 增强**：检索结果以 `[REF i] url=... ` 格式附加到 LLM Prompt
- **延迟**：均值 ~2186 ms，p50 ~2096 ms（比 LLM-only 多 ~338 ms）

### 4.4 PhishLLM (Multimodal Baseline)

- **模型**：Qwen-VL-Plus（多模态，文本+图像）
- **输入**：网页证据文本 + Base64 截图（无截图时退化为纯文本）
- **参考**：参考 USENIX Security 2024 PhishLLM 方法设计，作为多模态基线

### 4.5 Qwen-MM (img+text)

- **模型**：Qwen-VL-Plus（多模态）
- **输入**：URL + 标题 + 截图（不含文本片段，验证截图特征单独贡献）
- **延迟**：均值 ~2557 ms，p50 ~2450 ms（最慢）

## 第五章 实验结果与分析

### 5.1 实验环境

- **操作系统**：Windows 11
- **Python**：3.11
- **LLM API**：DashScope（通义千问）/ Qwen-VL-Plus
- **本地推理**：`sentence-transformers`（v2.7），FAISS（v1.8）
- **测试集**：`data/evidence/combined_evidence_mm.csv`（434条，其中钓鱼79条、良性355条）
- **截图覆盖率**：424/434 = 97.7%（基于 CSV 文件 `screenshot_path` 字段直接统计）

### 5.2 总体性能对比（5种方法）

| 方法 | n | Accuracy | Precision | Recall | F1-Score | 延迟均值(ms) |
|------|---|----------|-----------|--------|----------|------------|
| TF-IDF + LR | 434 | 0.9539 | 0.9538 | 0.7848 | 0.8611 | ≈0 |
| LLM-only | 434 | 0.8963 | 0.9474 | 0.4557 | 0.6154 | 1790 |
| **LLM + RAG (Ours)** | **434** | **0.9608** | **0.9697** | **0.8101** | **0.8828** | **2186** |
| PhishLLM (MM baseline) | 434 | 0.9309 | 1.0000 | 0.6203 | 0.7656 | 2299 |
| Qwen-MM (img+text) | 434 | 0.9286 | 1.0000 | 0.6076 | 0.7559 | 2557 |

> ⚠️ **重要说明（数据科学严谨性说明）**：本表中 LLM+RAG 方法的 F1=0.8828 存在以下潜在偏差需要读者知晓：
>
> 1. **索引与测试集完全重叠**：RAG 向量索引的 URL 与测试集 URL 100% 重叠（434/434）。这意味着对每个测试样本，其相似邻居均来自同一集合，属于"闭集评测"，不能完全代表对未见 URL 的泛化能力。
>
> 2. **Label 字段可见**：RAG 检索到的参考条目中包含 `label` 字段（见 `llm/classify_with_rag_local.py` 第82行，格式为 `[REF i] url=... label=1/0`）。统计分析显示：真实为钓鱼的样本，其检索到的参考条目中平均 86.6% 标注为 phish；真实为良性的样本，仅 8.6% 的参考标注为 phish。这种标签分布差异构成间接的泄露信号，LLM 在推理中可能部分依赖该信号而非纯粹语义判断。
>
> 3. **NoSelf 只是必要条件**：NoSelf 机制排除了自身 URL 的直接匹配，但无法消除邻居标签构成的泄露。
>
> **结论**：F1=0.8828 是**可完全复现**的真实数字（见 `data/predictions/mix_rag_noself_full.jsonl`），代表了系统在当前闭集设置下的实测性能。若需评估泛化能力，需重新构建持出测试集（测试集 URL 不出现在 RAG 索引中）并去除 Prompt 中的 label 字段后重跑实验。

### 5.3 核心结论

1. **综合性能最优**：LLM + RAG (NoSelf) 取得最高 F1（0.8828）和召回率（81.01%），相比纯 LLM 方法，召回率提升 **35.44 个百分点**，F1 提升 **0.2674**，验证了检索增强的显著效果。

2. **多模态方法特点**：PhishLLM 与 Qwen-MM 均实现**零误报**（Precision=100%），但召回率偏低（约 61%），说明多模态方法在当前 Prompt 设定下偏保守——几乎不产生误报，但会漏检约 39% 的钓鱼样本。

3. **延迟开销分析**：
   - TF-IDF+LR：≈0 ms（无网络调用）
   - LLM-only：~1790 ms
   - LLM+RAG：~2186 ms（比 LLM-only 多 ~396 ms，检索开销）
   - 多模态方法：~2300–2557 ms（图像编码额外增加延迟）

4. **文本模态 vs 多模态**：在当前实验条件下，RAG（纯文本）的 F1（0.8828）显著高于 Qwen-MM（0.7559），说明检索增强带来的收益（+0.2674 vs LLM-only）大于多模态视觉特征带来的收益（Qwen-MM vs LLM-only 约 +0.14）。

## 第六章 消融分析

### 6.1 RAG 检索的贡献

通过对比 LLM-only（F1=0.6154）与 LLM+RAG（F1=0.8828），可以定量评估检索增强的贡献：

| 指标 | LLM-only | LLM+RAG | 提升 |
|------|----------|---------|------|
| Recall | 0.4557 | 0.8101 | **+35.44pp** |
| F1 | 0.6154 | 0.8828 | **+26.74pp** |
| Precision | 0.9474 | 0.9697 | +2.23pp |

RAG 的主要贡献在于**大幅提升召回率**：通过检索已知钓鱼案例提供上下文，帮助 LLM 识别那些文本特征不够显著的钓鱼样本（LLM-only 的 FN=43，RAG 降至 FN=15）。

### 6.2 NoSelf 机制的必要性

不排除自身的 RAG 版本存在更严重的数据泄露（检索到自身URL及其标签），NoSelf 机制是维持实验有效性的必要设计。

## 第七章 局限性与未来工作

### 7.1 当前局限性

| 局限性 | 说明 | 影响 |
|--------|------|------|
| 闭集评测 | RAG 索引与测试集 URL 100% 重叠 | F1=0.8828 偏乐观，不代表泛化性能 |
| Label 泄露 | Prompt 中暴露检索条目的真实标签 | LLM 部分依赖标签信号而非语义 |
| 样本规模小 | 434条测试样本（钓鱼仅79条） | 结论统计效力受限 |
| 多模态局限 | 动态渲染页面截图可能不完整 | 部分截图质量差，降级为纯文本 |
| 时效性 | 钓鱼网站下线快，采集存活URL有偏 | 测试集可能偏向"长存活"钓鱼 |

### 7.2 改进方向

1. **修复 label 泄露**：从 RAG Prompt 中移除 `label` 字段，仅保留 URL 和文本特征，重新评测；
2. **构建持出测试集**：确保测试集 URL 在 RAG 索引构建时不可见，实现真正的开集评测；
3. **扩充数据集**：增加样本量至 1000+，改善统计可靠性；
4. **优化多模态 Prompt**：改进 Qwen-VL 的视觉分析提示词，提升召回率；
5. **轻量化部署**：探索本地小模型（如 Phi-3-mini）替代 API 调用，降低延迟与成本。
